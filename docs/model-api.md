# Model API

`oxide-ml` has two layers: the original graph-builder API and the model API. This
guide covers the model API, where a `Module` owns its parameters, a `#[model]`
method describes the forward pass, and `CompiledModel` turns the module tree into
an optimized graph. Start with `use oxide_ml::prelude::*;`.

## Quick start

```rust
use oxide_ml::prelude::*;

#[derive(Module)]
struct XorMlp {
    fc1: Linear,
    fc2: Linear,
}

impl XorMlp {
    #[model]
    fn forward(&self, x: Tensor<f32>) -> Tensor<f32> {
        let hidden = tanh(self.fc1.forward(x));
        self.fc2.forward(hidden)
    }
}

fn main() -> Result<()> {
    let model = XorMlp {
        fc1: Linear::with_seed(2, 8, true, 7),
        fc2: Linear::with_seed(8, 1, true, 9),
    };
    let input = Tensor::<f32>::from_vec(
        [4, 2],
        vec![0., 0., 0., 1., 1., 0., 1., 1.],
    )?;
    let prediction = model.predict(input)?;
    assert_eq!(prediction.dims(), vec![4, 1]);
    Ok(())
}
```

`predict` is generated by `#[model]`; see [proc-macros.md](proc-macros.md).
`Tensor<T>` here is the host-resident model-API tensor, not the statically
ranked `oxide_ml_core::Tensor<R, T>` (re-exported as `RankedTensor`).

## The `Module` trait

| Method | Purpose |
| --- | --- |
| `module_type` | Type name used in descriptors and checkpoints. Defaults to `"module"`. |
| `visit_parameters` | Discover parameters under a `ModulePath` without building a graph. |
| `forward` | Append a single-input forward pass to a `ModelContext`. |
| `forward_multi` | Multi-input forward pass; default requires exactly one input and calls `forward`. |
| `set_training` | Propagate train/eval mode. Stateless layers ignore it. |
| `is_training` | Current mode. Defaults to `true`; stateful containers override it. |
| `visit_tensors` | Visit concrete parameter tensors read-only, in stable name order. |
| `visit_tensors_mut` | Visit tensors for write-back; shared storage may be skipped. |
| `describe` | Record one hierarchy node. |
| `state_config` | Declare the KV-cache layout (`Ok(None)` when stateless). |
| `descriptor` | Build the full `ModuleDescriptor` tree. |

Blanket implementations exist for `Option<M>` (absent modules are skipped),
`Vec<M>` (applies modules sequentially with paths `0`, `1`, ...), `Box<M>`,
`Arc<M>` (shared modules; write-back is skipped when the `Arc` is shared), and
`()` (identity). `Sequential` stores erased modules and supports `new`, `add`,
`push`, `len`, `modules`, and `predict`.

### `ModuleList<M>`

`ModuleList<M>` is the typed collection counterpart of PyTorch's `ModuleList`:
it owns a homogeneous sequence of modules, assigns integer path segments
(`layers.0.weight`, `layers.1.weight`, ...), and can be indexed, iterated and
mutated before compilation.

```rust
#[derive(Module)]
struct Stack {
    layers: ModuleList<Linear>,
}

impl Stack {
    #[model]
    fn forward(&self, x: Tensor<f32>) -> Tensor<f32> {
        let mut hidden = x;
        for layer in &self.layers {
            hidden = layer.forward(hidden);
        }
        hidden
    }
}
```

`#[model]` rewrites module-collection loops so each iteration resolves to the
right parameter path; nested loops over `ModuleList`s work too. Methods:
`new`, `with_capacity`, `from_vec`, `push`, `insert`, `remove`, `pop`, `len`,
`is_empty`, `get`, `get_mut`, `first`, `last`, `iter`, `iter_mut`, `as_slice`,
`as_mut_slice`, `extend`, `into_vec`, plus `Index`/`IntoIterator` and
`FromIterator`. `ModuleList` itself implements `Module` by applying its contents
in order, so it also works as a plain field.

### Enum architectural variants

An enum deriving `Module` is a set of alternative architectures whose fields
share parameter paths. The derive dispatches `forward` to the only module field,
or to the field marked `#[module(body)]`; other module fields are still
registered, which keeps checkpoints stable when variants change. See
[proc-macros.md](proc-macros.md#enum-architectural-variants).

### Tied parameters

`TiedLinear<S>` reuses another module's weight instead of copying it. Both paths
resolve to one canonical parameter, one graph binding and one optimizer slot;
the alias is recorded in `CompiledModel::aliases()` and
`ParameterRegistry::aliases()`.

```rust
#[derive(Module)]
struct Lm {
    embed: Arc<Embedding>,
    head: TiedLinear<Embedding>, // TiedLinear::new(embed.clone())
}
```

`TiedWeightSource` is implemented for `Linear` and `Embedding`.
`TiedLinear::flattening(source)` additionally flattens `[batch, sequence,
hidden]` decoder states before the matrix product. Any module whose traversal
reaches the same tensor storage is aliased automatically, so custom tied
structures do not need `TiedLinear` specifically.

### Execution state

`Module::state_config` declares the KV-cache layout a model needs (`Ok(None)`
for stateless modules). `KvCache` is the reusable host implementation:

- per-layer `(kv_heads, head_dim)` shapes;
- `KvLayerConfig::shared_with(source)` for shared-KV layers that read another
  layer's rows instead of owning storage;
- explicit `reserve`/automatic growth with an error on shape mismatch;
- `append`, `append_many`, `keys`, `values`, `len`, `truncate`, `reset`;
- `ModelState` (`reset`, `sequence_length`) for runtimes that own one state per
  session. State is `Send` and has no interior mutability, so sessions cannot
  alias each other.

`StreamingGemma` uses this framework state for prefill and decode. See
[known-limitations.md](known-limitations.md) for the current device-residency limits.

`#[derive(Module)]` generates `module_type`, `visit_parameters`, `forward`,
`forward_multi`, `set_training`, `visit_tensors`, `visit_tensors_mut`, and
`describe`. See [proc-macros.md](proc-macros.md) for field attributes and
parameter roles.

## Parameter names and roles

Names are dot-joined module paths from the root. The model type is **not** part
of the name, and names never contain graph ids, so they survive graph rewrites
and compiler passes.

```rust
#[derive(Module)]
struct Block {
    fc: Linear,
    norm: LayerNorm,
}

#[derive(Module)]
struct Net {
    block: Block,
    head: Linear,
}
```

`Net` owns `block.fc.weight`, `block.fc.bias`, `block.norm.gamma`,
`block.norm.beta`, `head.weight`, and `head.bias`. A `Sequential` uses integer
segments: `0.weight`, `2.bias`, and so on.

| Role | Saved in checkpoints | Updated by the optimizer |
| --- | --- | --- |
| `trainable` | yes | yes |
| `frozen` | yes | no |
| `buffer` | yes | no |

If two module paths share the same tensor storage, parameter discovery treats
the second path as an alias of the first canonical parameter. Both names resolve
to one graph parameter and one optimizer slot. Registering the same name twice
is rejected. Parameters are bound to the graph by these names, so the store and
checkpoint never depend on construction order. The descriptor renders the
hierarchy:

```rust
let descriptor = model.descriptor()?;
println!("{}", descriptor.render());
assert_eq!(descriptor.parameter_count(), 6);
```

## Inputs and compilation

`InputSpec` describes one graph input. `batched` makes dimension 0 a shared
symbolic batch dimension and treats `dims` as the per-sample shape;
`unbatched` uses all dimensions as static.

```rust
// One graph for any batch size; each sample is [4].
let batched = InputSpec::batched("input0", [4]);

// A fixed [8, 4] input (including its batch dimension).
let fixed = InputSpec::unbatched("input0", [8, 4]);
```

Graph compilation has two levels. `BuiltModel::build` exposes the unoptimized
graph and parameter registry, and `.optimize` runs the compiler and memory
planner. Most code uses `CompiledModel` directly:

| Constructor | Graph contents |
| --- | --- |
| `CompiledModel::compile(model, inputs, options)` | Forward only (inference). |
| `CompiledModel::compile_loss(model, inputs, target, loss, options)` | Forward + loss; no backward graph. |
| `CompiledModel::compile_training(model, inputs, target, loss, options)` | Forward + loss + backward. |

`ModelCompileOptions` defaults:

| Field | Default | Meaning |
| --- | --- | --- |
| `optimize` | `true` | Run compiler passes. |
| `memory_plan` | `true` | Run the memory planner. |
| `mode` | `ModuleMode::Eval` | Train/eval mode used while building the graph. |
| `gradient_registry` | `None` | Custom autograd rules; inferred from `custom_kernels` when absent. |
| `custom_kernels` | `None` | Registry used by `Op::Custom`. |

`ModelCompileOptions::training()` sets `mode` to `Train`; the `optimize` and
memory-plan flags stay at their defaults. `without_optimization()` disables both
compiler stages.

`CompiledModel` methods:

| Method | Result |
| --- | --- |
| `run(&ParameterStore<f32>, &[(name, &Tensor)])` | `Vec<Tensor<f32>>` model outputs. |
| `run_training(...)` | `TrainingOutput { loss, gradients, outputs }`. |
| `evaluate(...)` | Scalar loss; requires a graph compiled with a loss. |
| `parameter_store(&model)` | Store built from the module's current weights. |
| `write_back(&mut model, &store)` | Copy store values back; returns `WriteBackReport`. |
| `report()` | `ModelReport` (counts, passes, memory bytes, aliases). |
| `forward_graph()`, `training_graph()` | The compiled IR / autograd graph. |
| `input_names()`, `parameter_ids()`, `aliases()` | Stable name bindings. |

During training the **store is authoritative**: execution, gradients and the
optimizer all use it. `write_back` copies the updated values into the module
tree. Shared/aliased tensors are reported in `WriteBackReport::skipped_aliases`
and cannot be updated through the module tree.

```rust
let mut model = XorMlp {
    fc1: Linear::with_seed(2, 8, true, 7),
    fc2: Linear::with_seed(8, 1, true, 9),
};
let x = Tensor::<f32>::from_vec([4, 2], vec![0., 0., 0., 1., 1., 0., 1., 1.])?;
let y = Tensor::<f32>::from_vec([4, 1], vec![0., 1., 1., 0.])?;

let compiled = CompiledModel::compile_training(
    &model,
    &[InputSpec::unbatched("input0", [4, 2])],
    InputSpec::unbatched("target0", [4, 1]),
    &MSELoss::new(),
    ModelCompileOptions::training(),
)?;
let mut store = compiled.parameter_store(&model)?;
let output = compiled.run_training(
    &store,
    &[("input0", &x), ("target0", &y)],
)?;
let mut optimizer = AdamW::new(0.05)?;
optimizer.step(&mut store, &output.gradients)?;
compiled.write_back(&mut model, &store)?;
```

## Losses

`Loss` has `name`, `forward(&mut ModelContext, prediction, target)`, and a
`reduction` (default `Mean`). It is `Send + Sync`, so a `Trainer` can own it.

| Loss | Expected shapes |
| --- | --- |
| `MSELoss` | Matching prediction/target shapes. |
| `CrossEntropyLoss` | Logits rank 2 `[N, C]`; targets are class indices ranked 1. |
| `BCEWithLogitsLoss` | Same shape for logits and targets; numerically stable. |
| `HuberLoss::new(delta)` | Positive `delta`; matching shapes. |
| `NLLLoss` | Rank-2 one-hot targets matching the logits. |

## Built-in layers

All of these are `#[derive(Module)]`-compatible and keep stable parameter names.

| Layer | Shape notes | Parameters |
| --- | --- | --- |
| `Linear` | Last dimension must be `in_features`. | `weight [out, in]`, optional `bias [out]` |
| `ReLU`, `GELU`, `Sigmoid`, `Tanh` | Elementwise. | none |
| `Softmax::new(axis)`, `Softmax::last()` | Softmax over one axis. | none |
| `Dropout::new(p)` | Identity in eval; explicit error in train when `p > 0`. | none |
| `LayerNorm::new/with_shape/with_eps` | Normalizes trailing dimensions. | `gamma`, `beta` |
| `BatchNorm::new` | `[N, C, ...]`; batch stats in train, running stats in eval. | `gamma`, `beta`, `running_mean`, `running_var` |
| `GroupNorm::new(groups, channels)` | `[N, C, ...]`. | `gamma`, `beta` |
| `InstanceNorm::new(channels)` | GroupNorm with one group per channel. | `gamma`, `beta` |
| `Conv2d::new/with_config/without_bias` | NCHW input, OIHW weights. | `weight`, optional `bias` |
| `Conv1d::new/without_bias` | `[N, C, L]`; implemented as a `[N, C, 1, L]` Conv2d. | `weight`, optional `bias` |
| `Conv3d` | Not implemented; forward returns `Error::Unsupported`. | none |
| `MaxPool2d`, `AvgPool2d` | NCHW; `.with_padding(...)`. | none |
| `MaxPool1d` | `[N, C, L]`. | none |
| `Embedding` | Indices are F32 integral values. | `weight [num_embeddings, embedding_dim]` |
| `Attention` | Three `[B, T, D]` inputs via `forward_multi`; `Attention::causal()` constructor. | none |
| `MultiHeadAttention` | `[B, T, E]`; `.causal()`, `.with_seed(...)`. | `query.*`, `key.*`, `value.*`, `output.*` |
| `Rnn`, `Gru`, `Lstm` | Input `[B, T, D]`; returns last hidden `[B, H]`. | `cell.input.*`, `cell.hidden.weight` |

## Limitations

- The model API is F32-only. `cast` rejects any dtype other than the input's.
- `Dropout` is not stochastic: training with `p > 0` fails explicitly rather than
  applying a missing mask. Eval mode is the identity.
- `BatchNorm` does not update running statistics during training; eval uses the
  stored values (initially mean 0 / variance 1). Supply them externally or use
  `without_running_stats()`.
- `Conv3d` is a placeholder and returns an `Unsupported` error.
- Recurrent layers return only the last hidden state and accept no initial state.
- `Attention` must be called through `forward_multi`; a single-input call errors.
- `predict` compiles a fresh unbatched graph per call; use `CompiledModel` for
  repeated or batched inference.
